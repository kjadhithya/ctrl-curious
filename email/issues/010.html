>  Today, in brief
Design tools spent the week opening up to agents: Figma now lets Claude, Cursor or Codex call Weave's image and video models through its MCP server, and Code Connect 2.1 drops its setup wizard in favour of an agent skill for mapping components to code. Framer followed its MCP launch with an Assets panel that its own agents can organise. The catch, as the Design Systems Collective argues, is that cheap automated audits make every deliberate exception look like a bug, so systems need a way to record them. And with Apple's event tonight, the bigger interface question is what touch does to a desktop built for a cursor, which today's brief takes on.

A gated design review checklist that keeps AI concepts out of the spec
Pixso's free AI design review checklist runs a crit as a series of short passes, each with a pass or fail gate and a severity scale. Its most useful rule for AI-assisted teams: generated concepts are labelled and kept apart from approved requirements.

# Design review gates (condensed from Pixso) Severity: S1 blocker · S2 major · S3 minor (owner + milestone) 1. Intent user, one-sentence task, decision data noted 2. Hierarchy purpose and primary task clear in 5 seconds 3. Layout desktop + mobile rules for wrap, truncate, overflow 4. Components shared patterns reused; exceptions written down 5. States loading, empty, failed, retrying, permission-limited, success 6. Content long, missing and localised values tested; errors give a next step 7. Access names, focus order, contrast and target size set 8. Issues every S1/S2 closed or formally accepted 9. Handoff AI-generated concepts labelled, unverified behaviour listed 10. Release not claimed until the built product passes testing Tag taste comments as 'preference', not user impact.

>  10-minute brief
Designing for a desktop that gets touched
Apple's event tonight is widely expected to bring the first Mac with a touchscreen. According to Bloomberg's reporting, macOS will adapt its controls to whichever input you used last, so desktop UIs tuned for a precise cursor will start getting tapped.
 An input-adaptive interface keeps the same layout but changes target size, spacing and menu behaviour depending on whether the latest input was a finger or a pointer.
What has been reported so far
1
A macOS that adapts to input
MacRumors, citing Bloomberg: controls change with the most recent input, and the Dock and menu bar are tuned for touch, alongside the keyboard and trackpad.
 
2
Menus that open around the finger
Earlier Bloomberg-based reporting described a tap bringing up a context menu around the touch point, and tapped menu bar items enlarging their controls.
 
3
Tonight's event
Apple's Pro and tell event is on 28 October at 10am Pacific, 10:30pm in India; treat every detail above as reported until Apple confirms it.
How to design for it
01Size for the input, not the screen: on the web, use any-pointer: coarse to enlarge hit areas whenever touch is present, since viewport width tells you nothing here.
02Keep dense pointer layouts but pad the hit area: grow the clickable zone with padding or a pseudo-element towards 44pt for touch without moving the visual grid; 24 by 24 CSS pixels is the WCAG 2.2 AA floor, not the goal.
03Audit hover-only UI: tooltips, row actions that appear on hover and hover-to-open menus each need a tap or long-press route.
04Check where popovers land: a hand covers the screen below and beside the finger, so keep the likeliest action away from the palm.
05Test the switch itself: tap, use the trackpad, tap again, and make sure density changes don't reflow a list mid-task.
Why it matters to you
The Mac was the last major platform where you could count on a precise cursor, and pro tools, dashboards and design apps lean on small targets and hover. If touch arrives as an extra input rather than a separate mode, one interface has to handle both.
 Our take  The tips are our own advice, drawn from the reports and WCAG rather than from Apple, which has not published guidance yet.
