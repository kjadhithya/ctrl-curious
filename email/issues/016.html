>  Today, in brief
Apple has opened Siri AI to every developer in the 27.3 betas, so an app's content and actions can now be reached by voice and personal context through App Intents, which turns your intents into an interface of their own. Figma now lets the agent and Make read and create files in Google Drive on every plan, and Framer's agent can now build and analyse A/B tests in Convert. >  Case study
GOV.UK AI team, Government Digital Service · GOV.UK
Creating tools for scaling generated content
Personalised plans for life events like having a baby are generated only when someone asks, so there could be thousands of versions and no single page to sign off. Pete Kowalczyk and Dave Russell built a test runner instead: a bank of scenarios, versioned prompts split by plan, step and task, and a rubric of 21 code checks and 19 model-judged criteria, with a score such as 54 out of 56 per plan. The decision that made it work was keeping every criterion pass or fail, adding one only when it catches a failure they have actually seen, and reading pass rates per criterion rather than one overall score.
>  How they work
BM
Blair Metcalf
Principal UX engineer, Reddit
On How I AI, Blair Metcalf explains Reddit Proto, the internal tool behind about 700 prototypes, which the team says everyone in UX and product now uses.
Habits worth copying
 
Start every prototype from a scaffold that already holds the design system, components and patterns, with toggles for device, theme, user states like moderator, and mocked or signed-in real data.
 
Give feedback as structured annotations that carry the code location, the element, the change and the wider intent, then apply them all to the code in one go.
 
Hand off through a Figma MCP that maps frames to production components and drafts a short PRD a person approves before a draft pull request is written.
 Our take  The adoption figure is Reddit's own; the habit worth copying first is blocking navigation in a prototype so reviewers stay on the one decision you need from them.
 
>  Decision toolkit
Let the model build the interface, or answer in text?
As assistants start answering with charts, forms and controls, someone has to decide when a generated interface helps and when plain text is clearer. Andrii Ladanskyi argues the answer lives in your design system.
Compose from your components when
›  The needs and scenarios are well understood
›  A local control, like a slider, can recalculate without a new model call
›  The product has rules the model must never break
 
Fall back to text or a question when
›  The request is broad or poorly defined
›  No component in the catalogue fits the job
›  A half-built or streaming state would confuse more than help
Seen in the wild
ChatGPT Intelligent UI
Rolled out on 7 October; a reconstruction found about 70 native components in the client, with plain text still the default when it is clearest.
Rule of thumb  If a model can't tell from the component's description when not to use it, it shouldn't be generating with it.
 Our take  The columns are our grouping of the article's examples; its four starting steps are to audit the system for a machine reader, list what the model must never build, design the in-between states and decide the fallback early.
