>  Typeface spotlight
Cal Sans Text UI
The small-size interface cut of Cal Sans v2, drawn for 10 to 20px with wider spacing and a curved l to tell it apart from I. Its x-height sits at 71.5% of cap height, close to SF Pro and Inter, and its line box is cap-centred, so it can replace those fonts without re-tuning buttons; Google Fonts merged it on 24 November.

>  Steal this
A DESIGN.md starter your coding agent can read
DESIGN.md is Google Labs' open format for handing a design system to AI coding agents: tokens in YAML front matter, rules in plain prose, one file at the root of the repo. This skeleton follows the eight sections of the spec in their required order, so you can fill it in for one product this afternoon.
DESIGN.md
--- name: [Product name] colors: primary: "[#hex]" secondary: "[#hex]" tertiary: "[#hex]" neutral: "[#hex]" typography: h1: { fontFamily: [Family], fontSize: [px], fontWeight: [600] } body-md: { fontFamily: [Family], fontSize: [px], lineHeight: [1.5] } rounded: { sm: [4px], md: [8px], lg: [16px] } spacing: { xs: [4px], sm: [8px], md: [16px], lg: [24px] } --- ## Overview [Two lines on the personality: what it should feel like.] ## Colors - [Which colour drives interaction, and where it never appears] ## Typography - [Which style for headings, body, labels, numbers] ## Layout - [Grid, max widths, spacing rhythm] ## Elevation & Depth - [When to use shadow vs. border vs. none] ## Shapes - [Corner radius per component type] ## Components - Primary button: background {colors.tertiary}, radius {rounded.md} ## Do's and Don'ts - Do [one rule an agent keeps breaking] - Don't [one pattern you never want generated]
Fill the brackets from your existing tokens, keep each prose rule to one line, and add a Do's and Don'ts line every time an agent gets something wrong. Sections you don't need can be skipped, but keep the order.
Get the original
 Our take  The section order and token references come from the spec as explained on designmd.app; the bracketed prompts are ours. Start with Do's and Don'ts, which is where agents improve fastest.
>  10-minute brief
When an AI agent is the user: designing tools it can pick
More design requests now start in a chat with an assistant that calls a product's tools on someone's behalf. That makes the list of tools, their names and what they return an interface in its own right, and this week Canva showed it is worth redesigning.
 An agent-facing surface is the set of actions a product exposes to AI agents (through MCP, an API or a CLI), and it is designed like any interface: the agent has to understand each action, choose it confidently, give it the right inputs and get a predictable result.
Where it showed up this week
1
Canva MCP
Canva merged overlapping tools so agents, including smaller models, choose with less ambiguity and use less context, and added a tool that turns flat images into editable layers.
 
2
Figma's agent in FigJam and Slides
Connectors and attachments bring outside material onto the canvas, and the output is a structured Spec or an on-brand deck that people keep editing.
 
3
DESIGN.md
Google Labs' open format gives agents a design system in one readable file, so the rules travel with the repo instead of living in someone's head.
How to design for it
01Name each tool after the job a person wants done, not after your internal feature name, and merge tools whose descriptions an agent could confuse.
02Return results in an editable, native form with a link back to it, so a person can fix one detail in your product instead of rerunning the whole request.
03Show progress for long jobs and report success only after your system confirms it, never when the request was merely accepted.
04Keep the person's own permissions and plan limits in force for anything an agent does on their behalf, and say plainly when a limit blocked an action.
05Test the surface the way you would test a screen: give a smaller model ten real requests and log which tool it picks and where it guesses.
Why it matters to you
As more requests arrive through assistants, an agent may be the first thing to use your product, and a confusing tool list fails as quietly as a confusing menu; product designers are well placed to own those names, choices and outputs.
 Our take  The definition and the first and last tips are our own reading. The tool consolidation comes from Canva's announcement, and the progress, confirmation, edit-link and permission tips follow Canva's developer guidance.
